Wanderville UI Panel Spec
Oct 25, 2026 · @zenzen
Every UI surface in the Godot client, with the pixel size it is drawn at. The game's base
resolution is 1578 × 997 with canvas_items stretch, so every number below is in those
units — draw art at 2× if you want it crisp on a retina display.
Read this first
Almost none of the UI is image art today. It is drawn in code:
Scripts/components/wood_panel.gd builds StyleBoxFlat rectangles — a brown fill, a
6px border, 12px rounded corners, a drop shadow — and every panel in the game wears it.
That is why there is no folder of panel PNGs to replace. The only real UI art that exists is in
Assets/inventory/ : inventory.png , inventorySlot.png , InventoryRect.png ,
Inventory_Sprite.png , healthbarUnder.png , hotbar_selector.png , orangebox.png .
So "change all the UI" means one of two things, and it is worth deciding before you draw
anything:
1. Reskin the shared style. Swap the flat colours in wood_panel.gd for
StyleBoxTexture nine-patches. You draw roughly six tileable pieces and every panel
below changes at once. Sizes stop mattering — a nine-patch stretches to whatever the
layout gives it.
2. Draw each panel at its own size. More control, far more art, and each one has to be
wired in separately. This is the route the sizes below are for.
Most panels are containers that grow to fit their text, so the sizes in this doc are
minimums and design targets, not fixed canvases — except the inventory board, which is
a real fixed-size image.
The shared skin
Six small scripts in Scripts/components/ dress everything. Change wood_panel.gd and
you change most of the game at once.

whatever holds it.

inside the Social Lobby.

How I'd do it
Counting the tables above there are about 30 panels, but only 7 distinct widths — and
500 px alone covers six screens. Drawing 30 panels would be wasted work.
The short route: 9 pieces of art, every panel changes. Draw these as nine-patches with a
20 px margin, and I rewire wood_panel.gd and wood_button.gd to use them.
