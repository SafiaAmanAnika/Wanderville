# Local Setup (Beginner Guide)

This guide explains how to set up Wanderville on your machine for local development.

## Required Tools

- Git + Git Bash (Windows)
- Python (3.10+ recommended)
- Godot 4.x
- VS Code (or any editor)

Verify installs (optional):

```bash
git --version
python --version
```

## Clone The Repo

Run these in Git Bash (or your terminal):

```bash
git clone https://github.com/SafiaAmanAnika/Wanderville.git
cd Wanderville
git checkout authentication-and-database
git pull origin authentication-and-database
```

## Backend Setup

From the repo root, run:

```bash
cd code/server
python -m venv .venv
source .venv/Scripts/activate
pip install -r requirements.txt
cp .env.example .env
python -m alembic upgrade head
python -m pytest -q
uvicorn main:app --reload
```

Notes:

- Keep the terminal running while `uvicorn` is running.
- If activation fails on your machine, see Troubleshooting.
- `python -m alembic upgrade head` applies all pending database migrations. This is the only command needed to set up the database.

## Database Migrations

This project uses **Alembic** for schema migrations.

### After pulling new code

```bash
cd code/server
source .venv/Scripts/activate
python -m alembic upgrade head
```

This reads migration files in `migrations/versions/` and applies any that have not yet been run.

### Creating a new migration

After changing a model (e.g., adding a column to `Player`):

```bash
python -m alembic revision --autogenerate -m "describe_your_change"
```

This creates a new file in `migrations/versions/`. Review the generated `upgrade()` and `downgrade()` functions before committing.

### Rolling back a migration

```bash
python -m alembic downgrade -1
```

## Files/Folders You Must Not Commit

These are local-only artifacts and should never be pushed to GitHub:

- `.env`
- `.venv/`
- `wanderville.db`
- `test_auth.db`
- `test_auth_deps.db`
- `__pycache__/`
- `.pytest_cache/`
- `.godot/`
- `.import/`

If you accidentally created/edited any of these, remove them from staging before committing.

## API Testing (Quick Checks)

With the backend running at `http://127.0.0.1:8000`, test these endpoints.

1. `GET /health`
1. `POST /auth/signup`
1. `POST /auth/login`
1. `GET /auth/me`

You can test with a browser (for `GET /health`), curl, Postman, or the autogenerated docs (usually at `http://127.0.0.1:8000/docs`).

## Godot Setup

1. Open Godot 4.
1. Click Import or Open.
1. Select the project folder: `code/client`.

Godot notes:

- Do not commit `.godot/` cache.
- Only commit project/source content such as `project.godot`, scenes, scripts, and assets.
- Do not commit `.import/`.

## Troubleshooting

### ModuleNotFoundError

- Make sure the venv is activated: `source .venv/Scripts/activate`.
- Reinstall dependencies: `pip install -r requirements.txt`.
- Confirm you are in `code/server` when running backend commands.

### .env Not Found

- Create it from the example:

```bash
cp .env.example .env
```

### Database Not Created

- Run migrations from `code/server`:

```bash
python -m alembic upgrade head
```

- This creates all tables via Alembic. Ensure `wanderville.db` appears in the same folder.
- If the database is corrupted, delete `wanderville.db` and re-run the command.

### Username Already Taken

- Sign up with a different username, or delete/reset your local database and re-run migrations:

```bash
# WARNING: this deletes your local data
rm -f wanderville.db
python -m alembic upgrade head
```

### Port 8000 Already In Use

- Stop the process using port 8000, or run the server on another port:

```bash
uvicorn main:app --reload --port 8001
```

## World & Map Setup

Starting from Milestone 3, every player automatically gets a **World** created when they sign up. The world stores a `tiles` dictionary that maps coordinate keys (e.g. `"0,0"`, `"1,0"`) to tile types (e.g. `"grass"`, `"dirt"`).

### How it works

1. When a player signs up via `POST /auth/signup`, the backend creates a `World` row linked to that player.
2. The world starts with an empty `tiles` dictionary and the default name `"My World"`.
3. You can access your world via `GET /world/me` (requires authentication).
4. You can update tiles via `PUT /world/tiles` (full replacement) or `PUT /world/tile` (single tile).

### Manual testing

After signing up and obtaining a token, follow the curl commands in the [Manual Backend Test Guide](manual_backend_test_guide.md) under **Testing World Endpoints**.
